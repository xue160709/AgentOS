# User Needs Contract：全界面语音控制的用户核心关注功能

## 观察任务
- 用户：尚无正式 `USER_PROFILE.md`；本轮仅采用用户明确提出的“站在用户角度判断最关注功能，尤其是语音控制整个界面”，并用 3 个 E4 模拟情境补充观察。
- 情境：首次使用、高频跨页面操作，以及误识别、权限、Provider、跨窗口等中断恢复。
- 入口：Option+Space 或托盘打开独立语音命令窗，选择自动/命令/聊天模式后开始、停止、编辑并提交。
- 期望结果：确认用户对“全界面语音控制”的真实关注顺序，并把关注点转成可验证的结果需求，而不是只统计语义标记或路由数量。

## 共识、分歧与未知
- 跨视角共识：覆盖数量不是首要价值；用户更关注“理解正确、实际完成、状态可信、失败可恢复”的稳定闭环。三个 E4 视角重复出现不提升为真实用户证据。
- 特定情境：首次用户最关心可说范围与模式理解；高频用户最关心连续发令、跨页直达和上下文延续；失败恢复用户最关心录音可见性、取消生效、幂等与跨窗口隔离。
- 冲突：提交前编辑与风险确认能提高安全，但会降低免手效率；广泛长尾覆盖能提高能力感，但不透明转交会降低结果可信度。设计需要按风险分层，不能用同一交互强行兼顾。
- 待验证：真实目标用户及高频任务；真实环境中的识别准确率和端到端延迟；用户对三种模式的理解；30 类 Agent 转交任务的实际完成率；macOS 权限、Helper、全局快捷键、隐藏/关闭/重开的实机行为；用户是否真的要求全程免手操作。
