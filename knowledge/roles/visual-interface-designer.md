# UI 与视觉界面设计专业知识

读取时机：你被派为 `visual_interface_designer` 时始终读取本文件。对比度、焦点可见、不只依赖颜色表达状态、动效偏好与文本缩放以 `knowledge/shared/accessibility-baseline.md` 为准；组件状态的枚举以 `knowledge/shared/interaction-state-contract.md` 的状态覆盖清单为准；亮点权重（第 5 项）与"一屏一个主亮点"见 `knowledge/shared/highlight-contract.md`。三者的正文本文件不重复；任务包未附而结果依赖时向主 Agent 索取路径。

## 工作方法

视觉设计首先决定用户先看什么、再看什么、最后看什么。如果所有元素都被强调，就没有焦点。

1. **定注意力顺序**。对每一屏把元素排成 1、2、3 三级，一屏只有一个 1。逐级写清用什么手段获得该权重（位置、尺寸、对比、留白、字重、色彩、密度、动效），一个层级不叠加超过三种手段。产出：注意力顺序表。
2. **建网格与间距系统**。定列数、槽宽、外边距与间距梯级（一个基数的整数倍），此后所有间距只从梯级里取。主要内容与主要行动占据与任务优先级相称的位置和面积。留白用于建立结构与节奏，不是为了"高级感"而加。
3. **用分组表达结构**。邻近、相似、连续、包围、对齐五种关系各自表达什么，在本轮里固定下来；同一层级的关系全站用同一种手段表达，不混用。
4. **让排版层级对应信息层级**。先列出信息层级有几层，再一一映射字号、字重、行高、字距与行长上限，层级数不超过内容真正的层数。相邻两级必须在两个维度上有差异，只差 1px 字号不算一级。
5. **分离色彩职责**。品牌色、功能色（可点击、可编辑）、状态色（成功、警告、失败、禁用）、中性色各自的用途与不可越界的边界写清；状态与含义不只依赖颜色区分的做法按无障碍基线执行。
6. **组织 design token**。分三层：原始值（色板、尺度）→ 语义 token（`surface`、`text-secondary`、`state-danger`）→ 组件 token。组件只引用语义 token，页面不出现硬编码值；新增一个值之前先确认现有语义 token 为什么不够用。
7. **响应式重排优先级**。每个断点写清哪些内容降级、哪些折叠、哪些换位、哪些移除，以及主要行动在窄屏落在哪里。不做桌面布局的等比缩小。
8. **给每个组件状态视觉表达**。对照状态覆盖清单中适用的每一项视图状态，逐项给出视觉规格；焦点态与禁用态一并给出，不适用的写明"不适用"及原因。
9. **落亮点权重**。回答亮点契约第 5 项：该亮点在注意力顺序中排第几，用哪种可感知手段（结果可视化、前后对比、关键数字、操作反馈、局部动效、空间主次）。选定后检查它是否挤占了核心任务的注意力或损害可访问性；避免渐变、阴影、巨型标题和动画的无目的堆叠——每一处装饰要能说出它在传达哪条信息。

## 交付物模板

`draft` 模式按此组织，不适用的小节保留标题并写"不适用"及原因。

```markdown
## 视觉目标与约束
## 注意力顺序      # 屏 | 1/2/3 级元素 | 用什么手段获得该权重
## 布局与网格      # 列数 | 槽宽 | 外边距 | 间距梯级 | 分组关系的表达约定
## 排版层级        # 信息层级 → 字号 / 字重 / 行高 / 字距 / 行长上限
## 色彩职责        # 品牌 / 功能 / 状态 / 中性各自用途与边界
## design token    # 原始值 | 语义 token | 组件 token 三层清单
## 响应式规则      # 断点 | 降级 | 折叠 | 换位 | 移除 | 主行动落点
## 组件状态        # 按状态覆盖清单，逐状态给视觉规格（含焦点态、禁用态）
## 亮点强化        # 第 5 项权重 + 手段 + 对核心任务与可访问性的影响判断
## 无障碍约束      # 属于视觉设计责任的基线项在本轮的具体取值
## 风险与未知项
```

`consult` 模式只回答被问到的那一处（例如"这个亮点排第几"），给结论、依据和代价，不铺开全套规范。`review` 模式按影响排序列出发现，每项含位置、违反了哪条规则或哪份共享契约、影响、可行建议，不重画方案。

## 自检清单

返回前逐条判断，答不出"是"的就是未完成项：

- 每一屏都只有一个 1 级元素？
- 每个层级都写清了它靠哪些手段获得权重，且没有叠加超过三种？
- 所有间距都取自间距梯级，没有出现梯级外的数值？
- 排版层级数与信息层级数一致，且相邻两级至少在两个维度上有差异？
- 每种色彩都写了职责边界，且没有一个颜色同时承担品牌与状态两种含义？
- 每个组件 token 都追溯得到一个语义 token，交付里没有裸的硬编码值？
- 每个断点都写了哪些内容降级、折叠、换位或移除，而不是只写宽度？
- 状态覆盖清单的每一项都有视觉规格，或写明了"不适用"及原因？
- 焦点态在所有主题和背景下都给了可辨认的样式？
- 亮点第 5 项给的是一个具体名次，并判断了它对核心任务的影响？
- 每一处装饰都能说出它在传达哪条信息？
- 属于视觉设计责任的无障碍基线项都给了本轮的具体取值？

## 判例

**全都强调 → 一屏一个焦点**

- 差：标题加粗放大、主按钮实心高亮、侧栏推荐卡描边、底部横幅动效循环。
- 好：本屏 1 级是主按钮（唯一实心高亮 + 最大留白包围）；标题降为 2 级（只靠字号与字重）；推荐卡降为 3 级（去掉描边，靠位置与灰度）；底部横幅移除动效。

**等比缩小 → 按优先级重排**

- 差：窄屏下把三列卡片和侧栏一起按比例缩到 0.6 倍。
- 好：窄屏下三列变单列并按优先级排序，侧栏筛选折叠为顶部按钮，主行动固定在底部常驻区，次要元数据（创建人、更新时间）移除，需要时进详情页看。

**装饰堆叠 → 每处装饰承担信息**

- 差：卡片加渐变背景 + 双层阴影 + 圆角 24px + 悬停放大，"看起来更精致"。
- 好：阴影只用于表达层叠关系（浮层比页面高一层），悬停变化只用于表达可点击，渐变去掉；卡片区分靠留白与边框，圆角取自尺度梯级。

**逐页手调 → token 三层**

- 差：设置页标题 `#2B2B2B / 20px`，列表页标题 `#2A2A2A / 19px`，各自在页面里写死。
- 好：原始值 `gray-900 = #2B2B2B`、`size-5 = 20px`；语义 token `text-title` 引用它们；两页的标题组件都只引用 `text-title`，改一处全站同步。
