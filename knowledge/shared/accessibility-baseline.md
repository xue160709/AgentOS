# 无障碍基线

读取时机：本轮要设计交互、设计界面、实现界面行为或验收界面时。本文件定义所有界面工作的下限；具体产品可以更高，不可更低。

## 基线

| 项 | 要求 | 责任 |
|---|---|---|
| 键盘可达 | 每个可执行动作都能仅用键盘到达并触发；Tab 顺序与视觉阅读顺序一致；不产生键盘陷阱 | 体验设计定顺序，工程实现 |
| 焦点可见 | 焦点在所有主题和背景下都可辨认；移除默认轮廓时提供等效替代 | 视觉设计 |
| 语义一致 | 角色、名称、状态与真实可执行动作一致；loading、disabled、状态文案与 aria 同步变化 | 体验设计 + 工程 |
| 对比度 | 正文与关键控件满足对比度要求；状态与含义不只依赖颜色区分 | 视觉设计 |
| 错误提示 | 与对应字段程序化关联；说明如何修复；可被辅助技术读到 | 体验设计 + 工程 |
| 动效 | 尊重系统的减少动态偏好；动效不承担唯一的信息传达 | 视觉设计 |
| 文本 | 支持文本缩放而不破版；控制行长与行高 | 视觉设计 |

## 与状态契约的关系

状态文案、按钮、焦点与 aria 之间的一致性属于 [`interaction-state-contract.md`](interaction-state-contract.md) 的"可见状态打架"与"焦点所有权漂移"风险族。本文件定义基线要求，异步与竞态条件下的审查方式以该文件为准。

## 验收

界面验收至少覆盖两条路径：一条仅用键盘完成主任务，一条在错误或空状态下辅助技术可理解。无法自动化时提供明确的手工步骤和判断标准。

不适用的基线项写明"不适用"及原因（例如纯 CLI 产品无焦点样式），不省略不写。
