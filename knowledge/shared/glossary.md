# 共享术语

读取时机：需要统一"事实、外部证据、推论、假设、模拟观点"等跨 Skill 协作术语时。本文件只定义词义；各术语的执行规则在对应契约文件中。

## 已确认事实

已由用户明确说明，或由主 Agent 根据可核验材料确认，并允许用于后续工作的内容。

## 外部证据

来自可追溯公开来源、真实用户材料、系统观察或测试结果的信息。必须保留来源、日期和适用范围。强度分级、引用格式与过期处理见[证据标准](evidence-standards.md)。

## 推论

根据事实或证据得出的解释。推论不能自动提升为事实。

## 假设

尚待研究、实验或用户决定验证的判断。

## 模拟观点

模型从假想角色或场景生成的观点，只能帮助提出问题，不能证明真实用户需求或市场需求。

## 产品亮点

目标用户能够发现、理解、体验并相信的差异化价值。一个亮点何时成立、由谁回答哪一项、何时失效，以[产品亮点契约](highlight-contract.md)为准。

## 任务模式

任务包声明的交付深度：`consult`、`draft`、`review`、`revise`、`compare`。模式只改变返回内容的深度与成本，不改变角色的判断权、写入边界和搜索档位；定义见[角色公共行为准则](role-conduct.md)。

## 任务包

主 Agent 向 sub-agent 提供的精简中文任务说明，包含目标、事实、假设、路径、权限、交付和停止条件。

## Skill

主 Agent 使用的流程/工具入口，不是独立组织层。跨 Skill 稳定规则进入 `knowledge/shared/`，只服务单一 Skill 的步骤、命令、模板和参数留在该 Skill。

## 主 Agent

项目唯一的编排者和用户责任人，负责用户澄清、范围确认、任务包、派工、冲突裁决、根级共享产品状态与变更包状态、最终复核和汇报；`knowledge/shared/` 的写入边界见[编排规则](agent-orchestration.md)。

## sub-agent

按任务包执行专业工作并向主 Agent 汇报的单层项目角色；不向用户承诺，不创建、派发或管理下一级 Agent。

## Current / Planned / as-built

- **Current**：当前产品、设计或实现事实，不承载尚未实现的计划。
- **Planned**：已确认但尚未成为当前实现事实的计划内容。
- **as-built**：代码与已验证行为形成的实现事实。

## Acceptance

描述产品或模块“做完”条件的验收契约；正式通过必须有 `project-verify` 派出的 `quality_verifier` 提供的独立验证、验证日期和可定位证据。

## 路由声明

主 Agent 在进入多步骤流程前，根据用户意图和当前事实说明使用的处理路径；它是可见决策记录，不替代读取对应 Skill、产物契约或验收文件。

## 弱信号

未选答案、模型推断、竞品缺失、Demo 外观或代码现状等尚未确认的线索；可用于继续提问或风险提示，不能直接写成产品事实或正式 Guardrail。

## 实现自检 / 正式验收

- **实现自检**：实现职责按本轮风险做局部、最小充分的检查，不回写正式 Acceptance 通过状态。
- **正式验收**：由 `project-verify` 派出的 `quality_verifier` 按验收契约逐条验证，带日期和可定位证据，并由主 Agent 记录正式状态。

## 事务边界 / late event

- **事务边界**：提交或确认动作开始后，旧输入、回调和状态是否还能影响当前流程的明确界线。
- **late event**：事务边界、取消、切页或对象切换之后才到达的旧异步事件；必须被作用域或取消机制识别为失效。

## 公开 Web 搜索

读取公开网页并引用来源的研究行为，不包括登录、下载文件、使用账号、发送数据或改变外部状态。

## 外部操作

改变工作区之外状态的行为，执行前必须获得用户确认；需授权操作的清单以 `AGENTS.md`「写入、外部操作与汇报」为唯一定义。
