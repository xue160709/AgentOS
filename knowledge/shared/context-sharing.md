# Sub-agent 上下文共享规则

读取时机：需要决定 sub-agent 继承哪些对话、材料、证据或文件路径时，以及编写任务包时。

## 目标

让 sub-agent 获得足够完成任务的信息，同时避免完整对话、无关材料、原始日志和其他角色草稿造成上下文污染。

## 默认策略

主 Agent 默认不复制完整主线程，而是给 sub-agent 一个精简任务包，并提供需要读取的项目文件路径。稳定信息写入项目文档，避免每次重新说明或重新搜索。

## 继承层级

### 不继承历史

适用于边界清楚的研究、文档、设计、架构、实现、测试和审查任务。任务包必须完整包含目标、约束和相关路径。

### 继承最近若干轮

适用于用户刚补充了会改变结果的重要语义，但尚未写入项目文档的情况。只继承包含该语义的最少轮次。

### 继承全部历史

只适用于分析完整产品探索过程、决策演变或用户长期意图的任务。完成后应把稳定结论沉淀为文档，后续恢复按需共享。

## 任务包模板

```markdown
## 任务目标
需要得到什么结果。

## 背景与原因
为什么现在需要处理。

## 已确认事实
逐项写来源：用户原话/位置、正式产物路径+条款/ID+revision，或代码与验证路径。主 Agent 的签署必须可定位；sub-agent 草案不能列在这里。

## 提案与未决项
列出 Agent 建议、尚有互斥答案的事项，以及不得擅自推断的内容。

## 合同版本与失效项
当前 `change_id@revision`、确认范围、被 superseded 的旧项，以及不得消费的旧任务包/验证/review。

## 待验证假设
明确仍不确定的判断。

## 相关资料
列出需要读取的具体文件路径。

## 范围与所有权
必须保留项、允许改变项、禁止推断项；允许读取、修改和创建的路径，以及不可改变项。

## 搜索权限
是否允许公开搜索、搜索目的、来源要求和禁止的外部操作。

## 交付要求
需要返回的结论、文档或代码，以及验证要求。

## 停止条件
出现什么冲突、风险或缺失信息时必须交回主 Agent。
```

## 装配映射

任务包的"已确认事实"与"提案与未决项"两栏由主 Agent 从上游产物中抽取装配。**上游角色按主题组织自己的产物，不为特定下游角色分节，也不自行转交**；角色之间没有直接交接，每条路径都是"上游角色 → 主 Agent → 下游角色"。

| 下游要填的缺口 | 通常来自的上游字段 | 装进任务包的栏位 | 上游缺失时 |
|---|---|---|---|
| 范围与产品规则 | 用研的待完成任务与障碍、市场研究的选择环境、CMO 的主细分与价值主张 | 已签署的进"已确认事实"，其余进"提案与未决项" | 列为未决项，不由下游推断 |
| 用户问题与行为证据 | 既有研究产物路径、`USER_PROFILE.md` 的已确认条款 | 已确认事实（附路径 + 条款 + revision） | 交回主 Agent 判断是否派用户研究 |
| 市场、竞品与定价事实 | 市场研究的结论条目（含来源、日期、口径、强度） | 已确认事实，另附"可能过期的内容" | 列为未决项并写明所需证据强度 |
| 细分、定位与亮点 | PRD 的价值与亮点小节、亮点契约七项的当前状态与负责人 | 已确认事实 + 各项负责人与状态 | 亮点停在候选，不进界面强调与对外表述 |
| IA、旅程与状态 | PRD 的产品对象、业务规则、主流程 | 已确认事实（对象与规则逐条列出） | 回到产品定义，不在设计中就地补对象 |
| 视觉层级与 token | 体验设计的注意力顺序、页面职责、状态规格；CMO 的信息层级顺序表 | 已确认事实 + 已冻结的顺序 | 顺序未定时不进入视觉任务 |
| 技术边界与接口 | PRD 的产品对象与业务规则、体验设计的状态规格、既有 as-built 与 `docs/adr/` | 已确认事实 + verified as-built（附可复核证据） | 产品语义未定时回到产品定义，不由架构代定 |
| 实现 | 架构的接口契约与失败语义、体验设计的状态规格、模块验收契约 | 已确认事实 + 冻结接口 + 代码/测试白名单 | 保持 `blocked`，不由实现者补合同 |
| 验证与验收 | `prd/<module>/acceptance.md` 的条款 ID 与 revision、亮点契约的验收项 | 合同版本与失效项 | 返回 `BLOCKED`、`reason=CONTRACT_PROVENANCE` |

第三列是溯源闸门。sub-agent 的产物在主 Agent 签署前只能进"提案与未决项"——"上游角色已经确认过"不构成写进"已确认事实"的理由，只有用户原话、正式产物的路径+条款+revision，或可复核的 verified as-built 才构成。

一个上游字段可以被多个下游任务包消费；抽取不修改原产物，也不产生新的事实来源。

## 必须共享

- 任务目标、业务原因和成功标准。
- 已确认的用户要求、产品事实和决策。
- 每项已确认语义的精确来源、主 Agent 签署状态、当前 revision 与 superseded 项。
- Agent 提案与未决问题，必须和已确认事实分开。
- 当前范围、非目标、不可改变项和文件所有权。
- 必须保留、允许改变和禁止推断的行为边界。
- 与任务直接相关的 PRD、研究、设计、架构、代码和验收文件路径。
- 允许的搜索范围、写入范围和外部操作边界。

## 按需共享

- 最近对话中的重要语义。
- 原始访谈、完整市场资料和竞品页面。
- 大型日志、截图、设计参考和完整测试记录。
- 其他 Agent 的结论；默认只共享摘要和证据路径。
- 已否决方案；只有防止重复或比较取舍时才提供。

## 默认不共享

- 无关历史对话。
- 其他 Agent 的思考草稿和未经确认的中间结论。
- 大量原始搜索结果、构建日志和测试输出。
- 与任务无关的个人信息、密钥、账号和敏感数据。

## 防止重复获取

- 外部研究需要落盘时写入主 Agent 在任务包中指定的精确 `docs/` 路径，并包含来源、日期、结论和适用范围；`docs/` 不预设研究目录。
- 后续 Agent 先读研究摘要，只在资料过期、互相冲突或缺少当前问题时补充搜索。
- 原始资料与摘要分开保存；默认向其他角色共享摘要和原始来源路径。
- 搜索结果返回主 Agent 时只保留会改变决策的事实、证据强弱和未知项。

## 返回主 Agent

sub-agent 不返回完整过程记录，默认返回：结论、关键依据、建议或完成内容、使用的合同来源与 revision、冲突/未知项、需要主 Agent 决定的问题，以及重要文件路径。发现任务包和最新用户约束、正式产物或 revision 冲突时停止，不自行选择一个版本继续。
