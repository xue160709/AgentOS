# AgentOS Design System

> 状态：Current / 唯一视觉事实源  
> 版本：1.0  
> 更新日期：2026-08-30  
> 工程入口：[`src/theme/tokens.css`](../src/theme/tokens.css)、[`src/style.css`](../src/style.css)

本文件定义 AgentOS 产品界面的长期视觉与交互基线。它不是营销页风格指南，也不是独立于代码的第二套组件库。新增界面先遵守本文件，再复用现有 token、CSS 组件模式与 React 交互边界。

## 1. 产品与用户依据

AgentOS 是面向本地项目和长期任务的桌面 Agent 工作台。核心用户是需要同时管理项目文件、对话、技能、运行任务和可视化结果的开发者与知识工作者。

设计目标可以概括为：

> 为长期停留在桌面工作区中的专业用户，在高信息密度环境下提供安静、精确、可控的 Agent 协作体验。

关键情境：

- 用户会连续工作数小时，需要低视觉噪声和稳定空间记忆。
- Agent 任务可能持续运行、等待输入、失败或被取消，状态必须比装饰更醒目。
- 文件路径、代码、日志和模型名较长，界面必须支持截断、换行、复制和完整信息查看。
- 工作区同时包含导航、聊天、文件、Runtime 预览和设置，布局需要支持窗口缩放与面板重排。
- 应用默认中英双语，所有组件必须容纳长中文、英文和技术标识符。

## 2. 设计方向

### 2.1 设计旋钮

| 维度 | 值 | 含义 |
| --- | ---: | --- |
| 视觉变化度 | 3/10 | 克制、统一，主要依靠层级而非造型制造区分 |
| 动效强度 | 2/10 | 只解释状态变化和空间关系 |
| 信息密度 | 7/10 | 桌面专业工具密度，保持可扫描性和可点击性 |

### 2.2 核心原则

1. **工作内容优先**：用户内容、任务状态和下一步动作优先于品牌装饰。
2. **空间稳定**：导航、Composer、预览和状态区域尽量不因加载或流式输出跳动。
3. **状态可读**：运行、等待、成功、警告、失败不能只靠颜色表达。
4. **渐进呈现**：默认界面保持简洁，复杂配置和诊断信息按需展开。
5. **系统原生感**：尊重操作系统主题、窗口安全区、键盘习惯和桌面指针精度。

### 2.3 明确不采用

- 不使用“AI 紫 + 霓虹光晕”作为通用产品风格。
- 不用大面积渐变、发光或玻璃拟态表达智能感；macOS 侧栏系统材质是例外。
- 不把深色模式机械地做成纯黑背景或浅色值反转。
- 不用无意义的呼吸、漂浮、打字点动画替代真实运行状态。
- 不把营销页的大字号和巨大留白带入高频工作区。

## 3. 事实源与工程策略

优先级从高到低：

1. 当前产品行为和已确认业务规则。
2. 本文件。
3. [`src/theme/tokens.css`](../src/theme/tokens.css) 中的工程 token。
4. [`src/style.css`](../src/style.css) 与局部窗口样式中的现有组件实现。

技术栈为 React 19 + TypeScript + 原生 CSS。当前不引入通用 UI 框架；组件优先复用既有 `.btn`、`.btn-toolbar`、菜单、表单、Dialog、Composer、消息和工作区模式。相同交互在三个及以上场景出现时，再抽成 React primitive，避免只为视觉一致性制造过度抽象。

图标统一来自 [`src/icons.ts`](../src/icons.ts)，通过 [`src/icon-inline.tsx`](../src/icon-inline.tsx) 渲染。新增图标遵循 24×24 viewBox、1.8px 圆角描边、`currentColor` 和装饰 SVG `aria-hidden="true"`；只有图标的按钮必须在按钮层提供 accessible name 和 tooltip。

## 4. Foundations

### 4.1 颜色

产品采用中性灰阶作为结构色，蓝色只表示焦点、链接、选中或明确的信息动作。语义色必须使用语义 token，不直接在组件内选择色阶。

| 角色 | Token | 使用规则 |
| --- | --- | --- |
| 主表面 | `--color-token-main-surface-primary` | 页面、工作区、Dialog 主体 |
| 次表面 | `--color-token-main-surface-secondary` | 选中行、分段控件、代码/日志容器 |
| 三级表面 | `--color-token-main-surface-tertiary` | 需要更强分组时使用，不嵌套超过两层 |
| 侧栏 | `--color-token-side-bar-background` | 桌面导航；macOS 可叠加系统 vibrancy |
| 主文字 | `--color-token-text-primary` | 标题、正文、关键值 |
| 次文字 | `--color-token-text-secondary` | 说明、元数据、次要动作 |
| 弱文字 | `--color-token-text-tertiary` | placeholder、非关键时间；不承载必要信息 |
| 边框 | `--color-token-border-light/default/heavy` | 从分区到控件边界按强度选择 |
| 焦点 | `--color-token-focus-border/ring` | 键盘焦点、输入激活、可拖拽控件激活 |
| 信息 | `--color-token-info-foreground/background` | 信息状态、链接式提示 |
| 成功 | `--color-token-success-foreground/background` | 已完成、健康、保存成功 |
| 警告 | `--color-token-warning-foreground/background` | 降级、等待、风险提示 |
| 危险 | `--color-token-danger-foreground/background` | 失败、删除、不可恢复动作 |

主题规则：

- 跟随 `prefers-color-scheme`，应用代码不设置 `[data-theme]`。
- 浅色主表面是柔和灰白，深色主表面是 `#181818`；避免纯白/纯黑长时间高对比刺激。
- 正文与背景至少达到 WCAG AA 4.5:1；大字和非文本图形至少 3:1。
- 状态同时使用文字、图标或形状；红/绿不能成为唯一差异。
- 生成式卡片允许拥有自己的数据色板，但其文本、焦点和状态仍服从宿主 token。

### 4.2 字体

界面使用操作系统字体栈，代码、路径、命令和日志使用系统等宽字体。不得依赖联网字体，避免 Electron 首屏闪动与离线失效。

| 层级 | Token | 用途 |
| --- | --- | --- |
| 2XS | `--text-2xs` / 10px | 极短状态、图表辅助标注；不可用于正文 |
| XS | `--text-xs` / 11px | 时间、辅助说明、标签 |
| SM | `--text-sm` / 12px | 导航、紧凑控件、元数据 |
| Base | `--text-base` / 14px | 默认正文、输入、按钮 |
| LG | `--text-lg` / 16px | 强调正文、小标题 |
| Heading SM–LG | 18/20/24px | 页面与区块标题 |
| XL | `--text-xl` / 28px | 空态主标题；工作区内谨慎使用 |

规则：

- 正文默认行高 `--line-height-normal`；紧凑标签使用 `--line-height-compact`。
- 标题以 500–600 字重为主，不用全粗体制造层级。
- 连续阅读内容推荐 60–80 个拉丁字符宽；日志和代码区域不受此限制。
- 技术标识符允许 `overflow-wrap: anywhere`，可复制内容不得禁用文本选择。
- 数字状态和计时器使用 `font-variant-numeric: tabular-nums`。

### 4.3 间距与密度

基础单位为 4px（`--spacing`）。新增样式优先使用 `--space-*`，旧样式可继续使用 `calc(var(--spacing) * n)`。

- 紧凑图标间距：4px。
- 同一控件内部：8px。
- 行与行、字段与字段：8–12px。
- 卡片内部：12–16px。
- 区块间：20–32px。
- 页面主内容水平内边距：窄窗 16px，常规桌面 24–32px。

桌面指针控件可使用 28/32/36px 高度；触控环境或粗指针模式使用至少 `--size-target-touch`（44px）的可点击区域。视觉图标可以更小，但命中区域不能随之缩小。

### 4.4 圆角、边框与阴影

| 层级 | Token | 用途 |
| --- | --- | --- |
| XS/SM | 4/6px | 标签、紧凑按钮、导航行 |
| MD/LG | 8px | 输入、卡片、菜单、预览容器 |
| XL | 12px | 浮层、大卡片 |
| 2XL | 16px | 工作区外框、关键 Dialog |
| Full | 9999px | 状态点、胶囊按钮、开关轨道 |

默认用 1px 边框划分层级。阴影只用于真正悬浮的菜单、Popover、Dialog 和搜索面板；页面内卡片优先使用边框与表面色。`--shadow-xs` 到 `--shadow-2xl` 表达固定层级，不为单一组件创建近似阴影。

### 4.5 动效

- hover、focus、pressed：100–150ms。
- Popover、面板进入：150–300ms，使用 `--cubic-enter`。
- 退出：100–150ms，通常快于进入。
- 只动画 `transform` 和 `opacity`；尺寸变化必须证明不会造成布局抖动。
- 流式内容允许自然增长，不对每个 token 做逐字动画。
- `prefers-reduced-motion: reduce` 下移除位移、缩放、循环和非必要平滑滚动，功能状态必须保持完整。

## 5. 信息架构与布局

桌面壳层遵循稳定的三域结构：

```text
┌──────────────┬──────────────────────────────┬──────────────┐
│ Navigation   │ Primary workspace            │ Context pane │
│ 项目/任务/技能 │ Chat / Home / Settings / Run │ 文件/预览/详情 │
└──────────────┴──────────────────────────────┴──────────────┘
```

- 左侧导航回答“我在哪里、还有什么工作”。
- 中央工作区承载当前任务和唯一主操作。
- 右侧上下文面板展示文件、Runtime 或详情，不重复中央主任务。
- 顶部窗口 Chrome 只放全局导航、窗口级动作和当前上下文标题。
- Composer 固定在用户阅读路径末端；流式输出不得将它推离可达区域。

响应式按能力而非设备名处理：

| 可用宽度 | 行为 |
| --- | --- |
| ≥ 1180px | 可同时显示导航、主工作区和上下文面板 |
| 760–1179px | 主工作区优先；上下文面板按需打开或压缩 |
| 360–759px | 单主面板；侧栏和详情改为覆盖层或独立返回路径 |

任何宽度下：

- 主流程不依赖页面级横向滚动。
- 面板拖拽必须有键盘或菜单替代，并限制最小/最大宽度。
- 窗口标题栏、安全区和固定 Composer 不遮挡正文或 CTA。
- 在 360px、760px、1024px、1440px，以及 200% 字体缩放和长文本下验证。

## 6. 组件规范

### 6.1 通用状态合同

每个可交互组件按适用范围实现：`default`、`hover`、`pressed`、`focus-visible`、`disabled`、`loading`、`error`。可选择组件还需要 `selected`；异步结果需要 `success` 或可持续的完成反馈。

- hover 只是增强，不能承载唯一动作。
- `focus-visible` 使用 2px 清晰焦点边界，焦点顺序与视觉顺序一致。
- disabled 必须同时阻止事件并降低视觉权重；不能只改透明度后仍可点击。
- loading 立即出现并防止重复提交，同时保留动作文字语义。
- error 靠近问题位置，说明原因和修复动作，并通过 `role="alert"` 或 live region 通知辅助技术。

### 6.2 按钮

- Primary：当前作用域唯一主要推进动作，通常每个面板不超过一个。
- Secondary：安全、可逆的常规动作。
- Ghost/Toolbar：导航和工具动作，不与主操作竞争。
- Danger：只用于破坏性动作；标签必须说清对象，例如“删除此配置”。
- Icon-only：提供 accessible name、tooltip 和至少 28px 桌面命中区。

按钮标签使用动词开头。运行中保持原宽度，避免“运行”变成“正在运行…”时造成布局跳动。

### 6.3 导航、列表与 Tabs

- 当前项使用表面、文字权重和必要时的标记共同表达，不只改变文字颜色。
- 行高保持紧凑但命中区域完整；尾部动作仅在 hover 出现时，键盘 focus-within 和触屏必须同样可见。
- Tabs 使用 `role="tablist" / tab / tabpanel`，方向键切换与焦点行为遵循 ARIA 模式。
- 列表支持空、加载、部分结果、错误和刷新状态；长列表采用分页、虚拟化或分段加载。

### 6.4 Composer 与表单

- Composer 是聊天主操作，附件、模式、模型和发送按“输入内容 → 调整上下文 → 提交”排序。
- 发送、停止和等待输入必须有互斥且稳定的状态。
- 表单 label 永久可见，placeholder 只给示例。
- 校验不清空用户输入；密码和密钥默认遮挡，并提供可访问的显隐控制。
- 设置页的保存状态应在字段区或底部操作区持续可见，不能只用短暂 Toast。

### 6.5 消息、活动与工具调用

- 用户输入和 Agent 输出靠对齐、表面和内容结构区分，不使用高饱和对话气泡。
- 思考、工具、活动和结果属于同一次运行的时间线，默认摘要，按需展开细节。
- 正在运行、等待用户、已完成、失败和已取消均提供文本标签；计时信息不代替状态。
- Markdown、代码、表格和图表必须允许选择、复制和横向局部滚动。
- 长输出优先分段和锚点，不用无限嵌套卡片。

### 6.6 卡片与生成式 UI

- 卡片只用于形成明确对象边界：任务、数据结果、运行实例或可执行插件。
- 卡片标题区包含对象名、状态和最多两个高频动作；其余动作进入菜单。
- 小/中/大尺寸保持同一信息优先级，小尺寸裁剪次要信息而非缩小所有文字。
- 生成式 UI 必须继承宿主文字、焦点、圆角和状态 token；自定义配色不能影响可访问性。
- 示例数据必须明显标注，不与真实项目数据混淆。

### 6.7 Dialog、Popover 与菜单

- Dialog 打开时焦点进入首个合理控件，关闭后回到触发点；Esc 关闭非阻断 Dialog。
- 破坏性确认明确对象、后果和可恢复性；可撤销时优先提供撤销。
- Popover 与菜单贴近触发点，在窗口边缘自动翻转或收缩。
- Toast 只承载短暂确认，不能是错误详情或唯一撤销入口。

### 6.8 Runtime、文件与日志

- Runtime 预览和日志是工作区对象，不是装饰 iframe；显示状态、作用域和恢复动作。
- resize handle 需要可见 focus、方向 cursor、数值反馈和键盘替代。
- 文件树保留层级、当前文件和项目边界；截断路径可通过 tooltip、详情或复制获取完整值。
- 日志使用等宽字体、保留换行、支持选择复制，并限制自动滚动对用户阅读位置的干扰。

## 7. 内容、媒体与数据

- 文案使用用户语言：项目、任务、技能、运行、文件；避免把内部 IPC、adapter 或 store 名暴露给用户。
- 状态文案说明“发生了什么 + 可以做什么”，错误不只显示错误码。
- 时间优先显示相对时间，诊断和详情同时提供绝对时间。
- 图片声明尺寸，提供用途匹配的 alt 和失败回退；装饰图使用空 alt。
- 图表趋势用折线、比较用条形、构成谨慎使用饼/环图；标明轴、单位、时间范围、数据源和更新时间。
- 图表不能只靠颜色区分系列，必须补充标签、形状、线型或可访问摘要。

## 8. 无障碍下界

- 所有功能可用键盘完成；禁止无语义容器模拟按钮。
- 可见焦点不可移除，焦点不能落入不可见面板。
- Dialog、菜单、Tabs、树和列表遵守对应 ARIA 语义与键盘模式。
- 文本对比度 ≥ 4.5:1，UI 边界与焦点 ≥ 3:1。
- 颜色不是唯一状态信号；错误和异步结果可被辅助技术感知。
- 支持 200% 缩放、长文本、中英混排和 `prefers-reduced-motion`。
- 触控目标至少 44×44px；拖拽、右键和 hover 动作都有替代路径。

## 9. 性能与稳定性下界

- 首屏壳层不等待非关键数据；各区域独立显示 loading/error/retry。
- 避免请求瀑布和全页骨架；骨架尺寸必须接近最终内容，防止布局位移。
- 高频输入、搜索、resize 和 scroll 做节流/防抖；连续尺寸值不要驱动整棵 React 树重渲染。
- 长列表分页或虚拟化，流式消息按批次合并更新。
- 图片按视口加载并声明尺寸；第三方脚本不能阻塞聊天、文件或 Runtime 主流程。
- 只在测量证明有效后使用 memo；effect 依赖优先使用稳定的 primitive。

## 10. 反模式

- 同一语义出现多个近似灰色、圆角、阴影或按钮版本。
- 在组件里写固定浅色值，导致深色模式依赖 fallback 或失真。
- 只在 hover 显示动作，却没有 `focus-within`、触屏或菜单入口。
- 用 Toast 报告不可恢复错误，或提交失败后清空输入。
- 用颜色点代替状态文字，或用动画代替真实进度。
- 在设置页堆叠多层卡片和边框，让层级比内容更醒目。
- 为“AI 感”引入渐变、霓虹、拟物机器人图标或持续脉冲。
- 页面级绝对定位和固定像素宽度破坏窗口缩放。
