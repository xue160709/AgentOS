代价和风险

用户会怎么感受这些缺口模拟心声 E4 · 非真实用户语录

F1 失败不知因：「它说『需要处理』，但没说要处理什么。我得重新点进去翻聊天记录才知道。」
F2 假备份：「它说『继续显示上一版』，可我从来没见过任何版本——是我操作错了吗？」
F4 信任时刻：「它说要跑 npm run build……我 out/ 里已经有构建好的东西了，为什么还要再构建？」（秒开后）「它到底跑没跑那个命令？」
F5 死等：「窗口都打开了，我想先把需求打出来，怎么打不了字。」
F6 权限死循环：「它说没有权限，可我点的按钮就叫『用 AI 修改』——那这个按钮为什么还能点？」
F7 重启断裂：「昨天还提示『需要处理』，今天怎么又是『可以开始修改』了？是修好了，还是那个提示本来就不重要？」

  • 已有产物零进程直开、last-good 与信任持久化、stale 检测诚实。
